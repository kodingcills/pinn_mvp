# Immutable Authorization and Signature Protocol (v1.1)

**Current status: signature *specification*, not an operational Tier 3 gate.** Use RFC 8785 (JCS) canonical JSON and RFC 8032 Ed25519 from maintained libraries. Never treat ordinary `json.dumps(sort_keys=True)` as a general JCS implementation; its numeric/Unicode serialization differs.

1. Strictly parse `authorization-payload.json` and `approval-envelope.json` as I-JSON, rejecting duplicate object keys, invalid numeric constants, lone surrogates, unknown critical fields, and nonconformant schemas. Validate date/time strings with `Draft202012Validator(..., format_checker=FormatChecker())`. Implement expiry/nonce/key-authorization checks separately; JSON Schema cannot do them.
2. Compute `payload_digest = "sha256:" + hex(SHA256(JCS(payload).bytes))` over **the entire immutable payload**, including its nonce, expires_at, analysis plan, budget and output release policy.
3. Construct the unsigned **envelope** object with `schema_version`, `request_id`, `payload_digest`, `signer_key_id`, `approver_id`, `decision`, and `signed_at`. No `signature_ed25519_base64` yet.
4. **The exact bytes to sign** are `RFC8785_JCS(unsigned_envelope)` encoded as UTF-8; sign with Ed25519 under a privately held human authorization key. There is no extra prefix or unsigned side-channel field in v1.1. The signed message includes `decision`, so changing `REJECTED` to `APPROVED` invalidates the signature.
5. Place standard-base64 encoded 64-byte Ed25519 signature in `signature_ed25519_base64`. On verification, remove **only** that field, JCS-canonicalize the remaining envelope, and verify against the trusted public key identified by `signer_key_id`.
6. After signature verification, independently check (a) `APPROVED` decision, (b) approver identity/permission, (c) `request_id` matches the immutable payload, (d) independently recomputed payload SHA256 digest equals the signed `payload_digest`, (e) signed approval and payload not expired, (f) one-time nonce unused, (g) exact approved code/container/scorer/analysis digests, and (h) preflight gates. Failed checks block the run.
7. State changes live in an **append-only run ledger**; no signed field is mutated to represent `RUNNING`, `SCORED`, etc. Runner privately records sealed set allocation according to the authorized allocation rule; the candidate never chooses or sees private seeds.

Test plan: approve and reject signatures using **test-only ephemeral keys**; mutate each signed envelope field (especially `decision`) and the payload to verify failure; reject replayed nonce, expired approval and wrong signer; check JCS vectors with complex number/Unicode cases using a conformant library. The included package does not ship private keys, a complete signer, a protected runner, or an authorized Tier 3 capability.
